# Atlas SDK

The consumer entry point exports the S1 HTTP client, Asset report helpers, generated public Protocol types, schema-driven validation adapters and the implemented queued coordinate Move To Catalog. Full synchronization remains future work. The [Slice 0 fixture](../tests/contract/README.md) uses these same adapters against separately generated test-only paths.

`createAtlasClient({ baseUrl, credential, fetch?, timeoutMs?, maxJSONBytes?, bootstrapContext? })` requires HTTPS and a caller-owned credential supplier. The initial qualified platform is Node 24. Its default transport uses ordinary system trust with bounded single-member gzip decoding; a supplied fetch is an explicit adapter whose encoded-byte and compression guarantees must be qualified independently. The package entry point loads no Node transport until its first default-transport request. Call `discover()` first; health discovers the current Dataset without sending a stale Dataset header. Before first enrollment, `bootstrapContext: { datasetId, protocolVersion }` accepts authenticated deployment/Operator-provided nonsecret discovery metadata. The Asset still sends its own prepared credential and grant, and only registration may transmit until successful registration or discovery. Resource methods expose typed complete response envelopes. Protected `documentation()` and `openapi()` preserve their HTML and raw-document representations. List/history methods accept typed pagination queries; callers carry the opaque `next_cursor` forward.

JSON reads include `read_context` with HTTP source and the observed Core commit cursor. List methods accept typed filters under the [query contract](../docs/topics/sdk.md#query-and-status-contract), including empty selections; the SDK encodes array values as JSON query content. A call's deadline starts before credential acquisition and continues through transmission. Credential timeout returns `not_submitted`, and a late credential cannot transmit the expired operation. A supplied fetch must honor the request's AbortSignal as standard fetch does; the default Node adapter provides the qualified transport bounds.

For explicit installation trust in Node, import `createHTTPSFetch` from `@atlas-field-systems/sdk/node` and supply its `ca`, finite timeout and JSON byte bound. Ordinary TLS verification stays enabled. The transport supports the Protocol's bounded single-member gzip encoding and selects request compression only after receiver advertisement and when the complete HTTP message is smaller.

Prepare mutations with `prepareRegistration`, `prepareTask`, `prepareCheckin`, `prepareReport`, `prepareEdit`, `prepareStatus`, `prepareTaskReport`, `prepareCancellation` or `prepareDeletion`. Persist the returned frozen descriptor before `submit`. It includes the original body, Dataset and edition, without credentials. `restoreMutation` validates retained JSON without changing source timestamp spelling or null/omission. Outcomes discriminate as `accepted`, `rejected`, `unknown_outcome`, `dataset_invalidated` or `not_submitted`; every mutation outcome carries its unchanged typed descriptor. A lost, incomplete, invalid or timed-out reply cannot establish rejection; writes never retry automatically. The caller may deliberately resubmit the same retained descriptor. Discovery of a replacement Dataset refuses old descriptors before transmission and rejects delayed old replies.

`createAssetClient` receives an externally owned process signer and replacement authorizer. `prepareAuthority` composes the signed candidate check-in; `observeAuthority` takes its validated accepted response before ordinary reports. `prepareCheckin`, `prepareReport`, `prepareStatus` and `prepareTaskReport` reserve one shared sequence and sign unchanged source facts. `snapshot()` exposes the counter/process seed for caller retention. Restore the same process key, generation and next sequence together; a replacement process uses a new signer and authorized transfer. Persist the updated counter and prepared descriptor together before transmission.

`reconcile` reads outstanding assigned work and accepts a typed externally retained execution snapshot. It returns prepared historical reports, eligible work and held IDs without executing or submitting anything. Completed/running/suspended work is not dispatched. Unknown work and its continuation remain held. Known-origin recovery requires retained `originalReport` fields/timing so it cannot invent different null/omission or source facts under an old origin; each new source event must retain its own provenance. Retained pending reports of the current process remain original descriptors until explicitly resolved. Keys, credentials, disk storage, execution counts, arrival rules and explicit physical recovery remain Asset/runtime responsibilities. The [operational wire contract](../Atlas%20Protocol/operational-contract.md) defines the exact signing inputs.

`responseValidation(document, context, { maxJSONBytes })` supplies middleware for a transport client. It requires an explicit positive safe-integer JSON response bound and enforces that byte limit while reading, before decoding or schema validation. It checks declared response status/media type, required headers and present header schemas, and the referenced JSON schema before `openapi-fetch` returns interpreted data. Dataset/version context must agree with the selected context wherever declared. Validated Dataset UUIDs compare by identity across canonical, uppercase and UUID URN spellings; protocol versions compare exactly. JSON envelope Dataset context is checked too, including error envelopes. JSON validation parses a bounded clone, leaving the returned body available; declared raw JSON, binary and no-body responses retain their own representation. `ResponseValidationError` reports a typed reason, including `body_size` for oversized JSON, HTTP status and safe method/schema-path context; it makes no decision about mutation commitment or safe retry.

The [qualified response declarations](../Atlas%20Protocol/README.md#supported-schema-profile) use exact HTTP status codes, inline Response Objects and local Header Object references. Construction rejects `default`, status ranges such as `2XX` and other non-exact status keys with a configuration `Error` identifying the declaration and operation, including when mixed with exact statuses. This happens before requests, separately from runtime `ResponseValidationError` failures. Response Object `$ref` resolution remains unqualified; local Header reference support does not qualify a general OpenAPI resolver.

Responses with no content declaration must contain zero body bytes. The adapter checks a clone, rejects the first nonempty chunk with the typed `body` reason and cancels the refused stream. Genuine empty replies retain their original Response and declared header/context checks.

Response construction visits only HTTP method entries, so shared path parameters and other Path Item metadata are permitted. Local Header Object references apply URI percent-decoding before JSON Pointer token decoding, preserving equivalent fragment spellings. Media matching validates the complete Content-Type syntax, then ignores token casing and valid parameters while JSON schema references retain the authored content key. Each declared `application/json` or `+json` response has its own validator, selected by the received media type. Construction rejects JSON declarations that collide after normalization, so one schema cannot silently replace another. JSON decoding rejects invalid UTF-8 before schema validation rather than silently replacing bytes. A status may offer JSON and binary content without applying the JSON validator to binary bytes. The [response checks](../tests/contract/README-97.md) cover these adapter boundaries. The caller selects the JSON limit; fixture bounds establish no production sizing or large-file memory guarantee.

`createAtlasClient` owns validation wiring and mutation-outcome handling under [connection setup](../docs/topics/sdk.md#connection-setup) and [mutation outcomes and retries](../docs/topics/sdk.md#mutation-outcomes-and-retries). The lower-level middleware remains available for independent contract qualification.

`contractValidator(document)` compiles references into the authored canonical document with the pinned Ajv implementation. It preserves omission/null/zero and performs no value coercion, default insertion or property removal. It supports the [qualified profile](../Atlas%20Protocol/README.md#supported-schema-profile).

`lookupCommand(name)` reads implemented queued coordinate Move To metadata from the installed canonical Protocol artifact and returns `{ protocolVersion, inputSchema, metadata, validateInput }`, or `undefined` for an unknown name. `metadata` is the Protocol's `x-atlas-command` object with its snake_case names unchanged. It performs no network request. The [Catalog evidence](../tests/contract/README-99.md) records the retained broader structural binding and S1 operational exclusions.

Consumer exports select compiled JavaScript and TypeScript declarations in `dist`, including the canonical Protocol artifact used by the Catalog. The `/protocol` export exposes the public generated declarations. The verifier rebuilds from absent `dist`, then loads the package by name with ordinary Node and checks consumer imports through both exports. Test-only routes, schemas, fixture SQL and response switches stay outside the consumer package. Public `paths` contains the 19 S1 method/path pairs. No publication or release-version range is established by this package.

The required TypeScript lint command uses the pinned compiler API for handwritten SDK and contract code. It rejects explicit `any`, suppression directives, nested type assertions and functions that only assert a parameter's type. Const assertions and `satisfies` remain supported. The shared compiler configuration also rejects unused locals and parameters. Prettier formats the same handwritten TypeScript and the JavaScript tooling; `npm run format:check` is a required check and `npm run format` applies it. Only `*.type-test.ts` files under SDK checks or contract tests may use `@ts-expect-error`; their required compiler checks fail when the intended error disappears. Other assertion invariants still require review under the [code conventions](../CODING_STANDARDS.md#types-and-language-conventions).

Run all required checks from the repository root:

```sh
python3 scripts/verify.py --bootstrap
```
