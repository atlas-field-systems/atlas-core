Local management TUI flow mocks

Static sketches for issue #31. Text, keys, layout and action names are proposals. These screens do not add backend policy or a public management API. The CLI and TUI would call the same private management boundary.

A. Overview console B. Command console C. Staged actions

A. Overview console

Selection stays in a status table. The right pane shows the selected target and available actions. A result line remains visible when an action finishes or becomes uncertain.

B. Command console

The operator types short local commands and reads a persistent transcript. Completion and uncertainty appear as separate result states. The command line offers the same actions as the CLI.

C. Staged actions

The operator opens a target, reviews the action's steps, then confirms. A small action ledger shows what is accepted, confirmed and still unresolved. Destructive actions use the same layout.

The screen sequence is illustrative. A selected flow can be recorded for the later implementation ticket without treating these mocks as implemented behavior.
