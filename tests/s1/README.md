# S1 coverage record

This is the requirement-to-evidence mapping for [spec #122](https://github.com/atlas-field-systems/atlas-core/issues/122): queued coordinate Move To through real Core, the TypeScript SDK in HTTP mode, the simulator and local management. Every row runs the real Core container over TLS with real SQLite and files, the shared `atlas-manage` CLI and, where an Asset is involved, the [simulator](../simulator/README.md) on the SDK Asset client. Expected outcomes are authored in the tests, independently of Core and the generators.

`python3 scripts/verify.py --bootstrap` builds the CLI and images (`scripts/build_core.py`) and runs this suite through `tests/s1/run.mjs` after the existing checks. The runner gives each test file a private directory and, after the worker exits for any reason, removes every Core container and Compose network of installations set up below it, then the directory. The suite needs a local Docker daemon, `openssl`, `unshare` and Python 3; the offline row also needs root or non-interactive `sudo`. A failed or unavailable prerequisite fails the run; it is never skipped.

## Supported combinations

Core and the SDK implement exactly the unpublished Protocol edition `0.0.0`; the S0 fixture editions `0.1.0`/`0.2.0` remain artificial. Both sides reject an unsupported edition (`setup.test.ts`). The Core release string is `0.1.0-dev`; a second image built as `0.0.0-release-probe` checks writing-release refusal. These are test facts, not published compatibility claims.

## Routes

The 19 method/path pairs are `GET`/`POST /entities`, `GET`/`PATCH`/`DELETE /entities/{entity_id}`, `GET /entities/alias/{alias}`, `POST /entities/{entity_id}/checkin`, `GET`/`PATCH /entities/{entity_id}/status`, `GET /entities/{entity_id}/tasks`, `GET /entities/{entity_id}/movement-history`, `GET`/`POST /tasks`, `GET /tasks/{task_id}`, `PATCH /tasks/{task_id}/status`, `GET /health`, `GET /readiness`, `GET /docs` and `GET /openapi.json`. `parity.test.ts` runs one 30-step scenario over all of them through the public SDK and through hand-built HTTPS requests with independently composed RFC 8785/Ed25519 report facts, on two isolated installations, and compares statuses, codes and normalized results. Only allocated identifiers, times, versions, cursors and the derived communication state are normalized. `GET /docs` is an HTML page the SDK deliberately does not wrap; it is checked directly.

## Engineering choices

The [direct IP bootstrap encoding](../../docs/topics/identity-and-access.md#direct-ip-bootstrap-encoding) carries deployment enrollment in the `Atlas-Enrollment` header. Reads return source instants in RFC 3339 form while signed and compared facts keep original spellings. Multi-member gzip handling and the `415` refusal are documented under [timestamp transfer](../../docs/topics/sdk.md#timestamp-transfer).

## Not established

- The offline row is verified with root; the non-root `sudo -n` path has not run in this environment.
- Interrupted Reset is exercised by killing the CLI once its durable pending record exists; the interruption lands at one of several later steps. Unavailable establishment inspection and an unreadable or conflicting pending record are not exercised.
- Incomplete Stop uses a private Docker client shim that fails `stop`; Core and storage are otherwise real.
- Packet duplication and reordering are modeled at the HTTP request level: identical descriptors submitted concurrently, twice or out of order. TCP-level impairment and bandwidth limits are not exercised.
- Change records are persisted with each commit but have no public read in S1; their delivery is S4 evidence.
- No byte, latency or memory budget is measured. Capacity, Full synchronization, Objects, Plugins, retirement, Pause/Resume and queue edits remain with their owning slices.
